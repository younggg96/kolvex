# Kolvex 股票估值分析产品方案

版本：评审稿 v1.0 · 2026-11-03（America/Los_Angeles）

交付范围：产品规划与开发拆分。本次未实现估值引擎、修改业务页面或操作数据库。

## 1. 产品目标与范围

让用户在个股页面回答四个问题：现在的股价处于什么估值水平，历史上如何变化，未来不同经营情景对应什么价格，以及修改假设后结果如何变化。

沿用之前讨论的约束：优先复用现有行情与 SEC 财报，不购买新的数据 API。新增数据订阅费目标为零，存储、服务器和开发成本另计。不能据此承诺免费获得完整历史分析师预测或全部公司的连续估值数据。

已确认网页端优先，兼顾手机端：网页端先完成计算与交互验证，手机端复用同一后端和产品口径。初期支持 USD 报价、USD 财报、US GAAP 的美国普通股，以数据通过校验的公司开放模型。ETF、指数、银行、保险、REIT、ADR 和非 USD 财报公司不进入第一批自动估值覆盖。

最终功能包含 PE、PEG、DCF。第一版先完整交付 PE 历史参考估值和情景分析，后续按模型的数据要求加入 PEG、DCF。每个模型独立标明可用状态，不用多个模型的平均数生成一个“综合目标价”。

三个不能直接复用为估值结果的地方：

1. 当前 SEC 解析器对同一期间优先选最新申报值。阅读财报可以这样展示，历史估值重建必须先按历史截止时间筛选，防止把后来的重述写回过去。
2. 当前 `ADDITIVE` 明确排除了 `eps_diluted`，TTM 路径没有生成 EPS；不能因为有 TTM 营收、净利润，就认为历史 TTM EPS 已经可用。
3. 当前行情请求没有显式指定 `auto_adjust`。估值应使用仅按拆股统一后的价格和每股财务数据，不能直接沿用包含分红调整的历史价格来算 PE。

## 3. 必须区分的三个产品概念

| 用户问题 | 产品名称 | 结果含义 |
| --- | --- | --- |
| 过去贵不贵？ | 历史估值 | 用各时点已向 SEC 申报的数据和固定版本规则重建，不宣称是当时 Kolvex 发布过的预测 |
| 现在处于什么水平？ | 当前估值 | 最新可用财报和明确假设下的模型参考值，与带时间戳的现价比较 |
| 未来可能值多少？ | 情景目标价 | 今天对未来目标日期的条件推演，可保存版本，不代表确定回报 |

参考图主要属于第三类。它的目标价区间、未来季度表和经营条件值得保留；要满足历史查看需求，还需要第一类的完整走势图。

历史估值另分两种视图：默认“按历史可得数据重建”；用户主动调整参数后，显示“用我的假设重算历史”。后者不覆盖默认历史，不称作过去真实预测。

第一版“历史可得”的范围限定为已向 SEC 申报的信息，不声称覆盖更早发布的新闻稿、电话会和全部市场信息。将来接入更早的官方披露时，作为新数据版本处理。

## 4. 信息结构与主要流程

入口：个股工作台新增“估值”Tab；概览页只放一条摘要和“查看估值”链接。复用现有股票页，不新增一级导航。`tab=valuation` 可直接定位，返回后保留股票和时间范围。

页面默认顺序如下。以下为结构示意，不含真实股票报价。

```text
股票名称 / 代码 / 当前价格 / 行情时间

当前估值                                  [查看计算依据]
模型 [PE] [PEG] [DCF]     口径与有效时间
保守值 ───────── 基准值 ───────── 乐观值
                  ▲ 当前价格
相对基准的空间 · 相对基准的折价/溢价 · 模型状态

历史走势
[股价与参考估值] [PE 倍数] [折价/溢价]
[1年] [3年] [5年] [全部]   默认3年
价格线 + 基准估值线 + 保守至乐观区间 + 财报事件
选中日期：当日收盘价、估值、EPS、PE、财报来源

未来情景
[下一财季] [第二财季] [第三财季]
目标期间 / 预计期末日 / 保守、基准、乐观目标价及空间

假设与经营条件                            [调整假设]
三种情景的 EPS / PE / 增长假设 / 经营条件 / 来源

数据与方法
财报期间 / 申报日 / 报价时间 / 模型版本 / 覆盖范围
```

当前价格如果超出估值区间，刻度仍包含当前价格，不能把价格点钉在端点而隐藏超出程度。三种情景用文字和线型辅助区分，颜色不承担买卖建议含义。保守价格也可能高于现价，其变化百分比应按计算结果显示。

网页端允许图表和选中日期详情并排。手机端依次堆叠，长按固定日期详情；未来季度采用可切换的单季度卡片，保留查看全部表格的入口。两端使用同一估值快照和四舍五入规则。

### 4.1 查看当前情况

用户打开估值页，先看到当前价、三情景参考区间、模型类型、财报有效时间和报价时间。默认展示 PE 的“历史 PE 参考估值”，避免将历史市场定价称作客观内在价值。

价格低于保守值时显示“低于模型参考区间”，在区间内显示“位于模型参考区间”，高于乐观值显示“高于模型参考区间”。不把区间内全部标成“合理”，也不直接输出“建议买入”。

### 4.2 查看历史变化

默认打开过去三年的“股价与参考估值”；没有三年数据时展示实际长度。用户移动十字线或点选日期，详情显示该日收盘价、三个参考值、有效 EPS、目标 PE、财报期间、申报日和重建方法。点财报事件，可查看估值变化前后输入差异及申报原文。

切换历史日期只更新历史详情，页首“当前估值”保持最新，并明确标为“当前”。不同视图保留相同日期与时间范围；用户能随时回到最新位置。

图上历史价格按日绘制；财报驱动的估值按有效事件阶梯更新。缺少输入时断线，不用插值或零补出平滑曲线。未来目标价不延伸为历史实线；默认放在独立的未来情景区。

### 4.3 调整并保存假设

“调整假设”打开面板。PE 支持逐情景修改目标 PE；未来推演另支持 EPS 年增长率和目标期间。PEG、DCF 在相应版本加入自己的参数，不能跨模型误用。

调整时即时显示预览、原值和差值，明显标明“我的模拟”。提供“恢复系统假设”；登录后可保存命名方案，例如“增长放缓”。未登录也能本地试算。保存的是数据快照、参数和版本，后续财报更新不自动改写旧方案；用户可另选“基于最新数据重新计算”。

用户默认只调整当前与未来。历史重算需主动开启“用我的假设重算历史”，并保留系统重建曲线用于对照。页面不提供更改历史事实数据的普通编辑入口。

## 5. 历史图的三个视图

| 视图 | 纵轴和内容 | 帮助用户判断 |
| --- | --- | --- |
| 股价与参考估值，默认 | USD/股；实际价格、基准线、保守至乐观区间 | 价格与模型参考值的距离如何变化 |
| PE 倍数 | 倍；TTM PE、当时历史样本的 P25/P50/P75 | 当前与过去的定价倍数有何不同 |
| 折价/溢价 | %；股价÷基准参考值−1，标出零线 | 偏离模型的程度、持续时间 |

保守至乐观是情景范围，不是统计置信区间。只有历史 PE 的 P25/P50/P75 和“历史分位”使用统计分位术语。

历史分位定义为：当前 PE 在此前窗口有效日 PE 样本中的位置，采用 `(小于当前值的数量 + 0.5 × 等于当前值的数量) / 有效样本数`。不包含未来和当日本身；固定展示窗口、样本量与起止日期。低分位仅表示相对自身历史较低。

时间范围可选 1年、3年、5年、全部；10年作为数据足够时的后续选项。历史估值和计算 PE 参考区间的回看窗口是两个独立设置。显示三年曲线而每个点回看五年，可能需要读取最多八年的基础数据。IPO 前和无覆盖部分不画数据。

## 6. 计算口径

### 6.1 全部模型共用的指标

设当前比较价格为 P，基准参考值为 V，目标日期情景价格为 T：

```text
相对基准的价格空间 = V / P − 1
相对基准的折价/溢价 = P / V − 1
到目标日期的价格空间 = T / P − 1
```

三者不能混用。例如 P=100、V=125，价格空间为 +25%，折价为 −20%。未来空间不包含分红、费用，也不是预期收益率。P 或分母无效时不生成百分比。

### 6.2 PE：第一版核心模型

```text
当日 PE = 当日仅拆股调整收盘价 / 同口径有效 TTM 稀释 EPS
参考值_s = 有效 TTM 稀释 EPS × 目标 PE_s
s = 保守、基准、乐观
```

默认目标 PE 来自公司自身过去五年、截止快照前一交易日的有效日 PE，分别取 P25、P50、P75。至少需要 252 个有效交易日和四个独立财报输入版本；不足时不自动推荐区间，允许用户明确输入自己的 PE。该门槛和分位选择属于 v1 产品规则，应保存版本。

参考倍数在新财务输入生效时重新估计，期间冻结，因此默认参考值呈阶梯变化；历史倍数视图本身每日变化。旧快照不会因今天新增样本而改变。不得用当日价格除 EPS 得到的同一个 PE 反算“合理价格”。

EPS 规则是第一版数据验收的重点：

- 优先使用来源和期间明确、可核验的稀释 TTM EPS；历史可由四个连续、同口径的直接披露单季 EPS 求和，并记录舍入差异。
- 年报披露的全年稀释 EPS 可作为对应完整十二个月的一个有效输入事件；不能将它伪装成下一季度更新后的 TTM。
- 当前 SEC 解析器需补充 EPS 数据路径。第四季度缺失时，不能把全年 EPS 减去前三季 EPS 当作精确 Q4 EPS；不同期间的稀释股数分母可能不同。
- 年度加当期累计减上年同期累计等桥接估计，如后续采用，须单独标为“推导 EPS”，记录方法、输入和误差验证；不能静默混入第一版默认曲线。
- 第一版无法验证的区间展示缺口或“TTM EPS 不完整”。当前 Yahoo EPS 可作为独立的供应商口径展示，不能无提示拼接进 SEC 历史序列。
- EPS≤0 时 PE 模型不适用；不以零目标价代替。异常高 PE 先核查分母和单位，不静默截断成一个看似正常的数值。

历史 PE 区间反映过去市场定价习惯。风险、增长和分配政策改变时，历史中位数未必仍适合当前公司；界面应允许用户查看并调整倍数。[方法参考：Damodaran 的 PE 估值讲义](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/lectures/pe.html)。

### 6.3 未来季度情景：对应参考图

未来三个公司财季，每个财季显示保守、基准、乐观价格与相对同一现价的空间。财政年度与自然年度分开，期末日未知时标注“预计”，不把期末日当财报发布日期。

第一版采用与 PE 历史一致的 TTM 口径，按用户输入或已审核预设的年化 EPS 增长率做机械外推：

```text
目标日期 TTM EPS_s = 当前有效 TTM EPS × (1 + EPS年增长率_s)^h
目标日期价格_s = 目标日期 TTM EPS_s × 目标 TTM PE_s
h = 从估值日到目标日的年数，按实际天数 / 365.25
```

这项功能明确叫“情景推演”，不称作分析师共识。没有可验证的公司预设时，增长率默认 0%，标明“盈利保持不变的机械假设”，用户可自行调整。不能把历史 CAGR 自动包装成未来增长预测。

单季 EPS 不能直接乘年度 PE；后续如加入 NTM 口径，应使用目标日期往后十二个月 EPS，并配套 NTM PE，单独切换，不与 TTM 结果混算。

以下仅为虚构股票 DEMO 的算例：现价100，TTM EPS=5；三情景 PE 分别16/20/24；为单独展示倍数影响，增长率均设20%，时间简化为3/6/9个月。

| 目标时间 | 保守价格 / 空间 | 基准价格 / 空间 | 乐观价格 / 空间 |
| --- | --- | --- | --- |
| 3个月后 | 83.73 / −16.3% | 104.66 / +4.7% | 125.60 / +25.6% |
| 6个月后 | 87.64 / −12.4% | 109.54 / +9.5% | 131.45 / +31.5% |
| 9个月后 | 91.72 / −8.3% | 114.65 / +14.7% | 137.58 / +37.6% |

三个情景可以同时改变盈利和倍数，但要公开每个输入。相同目标日期必须满足保守≤基准≤乐观；发生交叉时提示修改情景，不能静默交换名字。不得由基准目标价线性加减固定百分比来伪造三情景。

每个情景提供“数值假设、经营条件、条件依据”三个部分。经营条件可以是利润率、营收增速或产能等，但只有接入相应量化预测模型时才参与运算；纯文本条件标明为解释，不假装已经影响 EPS。每个事实附来源及日期，用户观点明确标为个人假设。

### 6.4 PEG：第二阶段

PEG 作为成长估值的辅助模型，在增长率有清晰定义、EPS 为正时开放。采用当前 TTM EPS 与未来三至五年年化 EPS 增长率，界面注明预测区间：

```text
隐含目标 TTM PE = 目标 PEG × 年化 EPS 增长率的百分数数值
PEG 参考值 = TTM EPS × 隐含目标 TTM PE
例如增长20%在公式中使用20，而不是0.20
```

增长≤0、基期亏损、预测范围不完整时不生成 PEG 目标价。默认不规定 PEG=1 必然合理，也不直接将当前单年预测推广到未来五年。无历史预测档案时，历史 PEG 只允许作为明确的规则重建或用户模拟，不称作当年分析师预测。[方法参考：Damodaran 的 PEG 局限](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/lectures/peg.htm)。

### 6.5 DCF：第二阶段，单独通过数据验收

默认规划五年显式预测期的 FCFF 企业现金流折现模型：

```text
FCFF = EBIT × (1−有效税率) + 折旧摊销 − 资本支出 − 营运资本增加
企业价值 = 未来FCFF折现和 + 终值现值
终值 = 第5年FCFF × (1+永续增长率) / (WACC−永续增长率)
股权价值 = 企业价值 + 可计入的非经营现金/资产 − 债务 − 其他优先索取权
每股价值 = 股权价值 / 模型对应的稀释股数
```

必须补足税率、折旧摊销、营运资本、现金、债务、少数股东/优先权益及股数的映射和期间定义。现有“经营现金流−资本支出”不能直接当成已核验的 FCFF，再套 WACC 并重复扣债。若改用 FCFE，应配股权成本折现，采用独立模型版本。

用户可调整营收增速、经营利润率、再投资假设、WACC、永续增长率、稀释路径。校验 WACC>永续增长率，输入完整、有限且股数为正；股权结果≤0时显示原因，不生成负数股价和上涨空间。展示终值占比与敏感性矩阵，避免用一个小数点精确的数字掩盖假设影响。银行、保险和 REIT 后续单独设计适用模型。

## 7. 历史数据与版本规则

每条财务事实至少保留：公司与证券标识、tag、单位、期间起止、财政年度/季度、数值、申报编号、申报日、可获得时间、来源链接、抓取时间、推导方法和所有输入引用。同一期间的多个申报版本必须共存。

计算历史时，先筛 `available_at ≤ 截止时点`，再在可用申报内选择对应事实。精确接受时间不可得时，保守地从申报日后下一交易日生效，并记录“日期级精度”。推导输入的有效时间取所有输入中最晚的时间。

后来的重述只能从其披露后影响默认历史。另行提供“按最新重述数据重算”时，要显式命名并保存独立数据版本。现有财报阅读页面可继续显示最新重述口径，不必改变其默认行为。

拆股时，历史价格与 EPS 统一到同一展示股本基准，保留拆股因子和原值；分红不调整 PE 价格。之后发生的拆股可用于统一展示单位，但不能更改历史 PE 和折价率。ADR 比例、不同股票类别、汇率或币种无法对齐时停止自动估值。

历史价格只用常规交易时段收盘价。当前卡片优先用最新可靠常规时段报价，盘后价作为单独信息；不把盘后价覆盖到历史收盘点。报价超过一个已结束的常规交易时段仍未更新时标记过期；周末沿用上一个交易日，显示日期。无法确认时间或币种时不输出当前空间。

财报覆盖不连续、财年变化、53周年度、单位或来源冲突都应进入质量状态。最后有效输入超过150个自然日未更新时提示“财务输入较旧”；不得无限延长曲线制造连续覆盖。缺失期间可查看原始财报，但不补造估值。

历史曲线有两类版本：一类是今天按某规则版本重建的历史；另一类是功能上线后真实保存的预测。保存后者时同时记录 `created_at`、`target_date`、模型和数据版本；查看修正历史时固定目标日期，不能把不同目标季度的价格连成“预测修正曲线”。

## 8. 状态与更新体验

| 状态 | 页面行为 |
| --- | --- |
| 首次计算、历史回填中 | 先展示已有当前结果与计算进度；历史区域允许继续浏览其他内容，提供取消等待/稍后重试 |
| 仅有部分历史 | 展示有效范围和原因，缺口保持可见，不让整个页面失败 |
| 股票/模型不适用 | 显示具体原因，例如亏损导致 PE 不适用；可看财报或切换可用模型 |
| 数据过期或来源暂不可用 | 保留带时间的最后成功快照；标明旧数据，允许重试，不改成零 |
| 模型输入不完整 | 显示缺哪些字段；已可用的其他模型继续展示 |
| 用户参数无效 | 在对应输入旁解释错误，保留上次有效结果并标明未应用修改 |
| 无已保存方案 | 显示“调整假设后可保存方案”，无需阻塞试算 |

报价按现有行情策略更新；财报新增申报后刷新，定期检查兜底。财报变化才触发官方快照重算；报价变化只更新比较位置、百分比和当日倍数。价格日线按交易日增量更新。参数拖动只基于缓存输入试算，不触发 SEC/Yahoo 读取；保存前由后端使用同一快照校验，避免网页和手机结果分叉。

AI 解读为后续能力，只解释已计算的输入、变化和情景条件，附来源。计算结果不依赖 AI 文本成功返回，AI 无权修改 EPS、目标 PE 或生成没有依据的经营事实。

## 9. 技术交付边界

估值引擎部署在现有 FastAPI，网页和手机共用。计算代码为可复现的确定性函数，输入带版本的财务快照与假设，输出数值、状态和来源。现有 SEC 读取层复用；历史版本标准化新增独立路径，不直接改变财报阅读接口。

建议新增后端 `app/services/valuation/` 与独立估值路由；网页新增 `StockValuation` 面板及 `lib/stockValuation.ts`；手机新增对应组件和客户端。名称为规划建议，实施时以仓库约定为准。

建议存储边界如下，具体 SQL 留到实现阶段：

| 数据集合 | 保存内容 | 访问原则 |
| --- | --- | --- |
| 原始财务事实版本 | 每次申报及来源、单位、有效时间 | 后端维护，客户端不直接写 |
| 价格与公司行动 | 交易日价格、拆股因子、数据版本 | 按证券和日期去重；更新保留来源 |
| 系统估值快照 | 财务输入引用、模型/规则版本、三情景、有效时间 | 由后端写入，按产品权限读取 |
| 用户估值方案及版本 | 所有人、参数、输入快照、目标日期、创建时间 | 用户只能读写自己的方案；重算另存版本 |
| 历史计算任务 | 回填范围、进度、失败原因、去重键 | 合并相同任务，限制并发 |

系统快照以财报/模型事件为主，图表服务按交易日投影；不为每次打开页面保存一整份重复曲线。缓存键至少包含证券、模型版本、数据版本、价格口径、时间范围及假设哈希，防止不同用户的参数污染系统结果。公开 schema 的表启用 RLS，个人方案按所有者授权；服务密钥只在后端使用。

拟定 API 契约：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/valuation/{symbol}/summary` | 当前价格、各模型可用状态、当前参考区间 |
| `GET /api/v1/valuation/{symbol}/history` | 按模型、区间、重建方式返回历史点及事件 |
| `POST /api/v1/valuation/{symbol}/simulate` | 指定快照与参数试算，不保存、不重新抓取外部数据 |
| `POST /api/v1/valuation/{symbol}/scenarios` | 认证后保存私人方案及其预测版本 |
| `GET /api/v1/valuation/{symbol}/scenarios` | 读取当前用户在该股票下的方案列表，支持跨设备恢复 |
| `GET /api/v1/valuation/{symbol}/scenarios/{id}` | 读取本人方案的输入快照、参数、结果和版本 |
| `GET /api/v1/valuation/jobs/{job_id}` | 首次回填的状态、覆盖范围和失败原因 |

长任务返回202与任务标识，已有部分数据可随任务状态返回。私人方案列表与详情按所有者授权，访问别人的方案不泄露内容。使用最新数据重算仍走试算、另存流程。下一阶段再确定归档和分享契约，不默认公开用户假设。

每份结果必须包含：证券、币种、价格和时间、财报期间、数据可获得时间、输入引用、模型版本、假设来源、结果类型（历史重建/系统当前/个人模拟/真实保存预测）、目标日期、覆盖范围、质量状态和原因码。历史 EPS 口径不同的系列不能伪装为同一条线。

## 10. 分期、依赖与验收

### 阶段A：数据可行性与样本核验，发布前置条件

以 NVDA、AAPL、MSFT 等目标公司为候选，核对五年以上价格、EPS、申报版本和拆股记录；选择真正通过校验的公司进入首批覆盖。额外测试亏损公司、短上市历史、财年非自然年、重述和拆股案例。候选列表不代表已经验证支持。

交付覆盖矩阵：每家公司的有效历史长度、可用 EPS 事件数、缺口原因、币种、是否支持三情景。必须证明能生成用户需要的有用历史，而不是页面接好但多数主流公司只有空白图。

### 阶段B：第一版 PE 完整闭环

交付当前参考区间、历史三个视图、三情景目标 PE、未来三财季机械推演、参数试算、来源追溯、私人方案保存、回填与降级状态。历史期间按覆盖矩阵开放，五年是目标，不是每股保证。网页端先发布可验收版本，同时固定供手机复用的接口、状态与交互规则。

第一版验收场景：

1. 选定历史日期后，只能看到该日截止前允许使用的申报；后来的重述不会改变此前结果。
2. 十拆一前后，在纯拆股情况下 PE 与折价率保持一致，展示价格和 EPS 同比例调整。
3. 缺 Q4 EPS、季度不连续、EPS≤0时，状态和断线正确，不产生虚假估值。
4. P=100、V=125时，空间为+25%、折价为−20%；全页与两端一致。
5. 当前价格超区间时仍显示真实位置；历史点不使用最新行情覆盖。
6. 同一输入快照与参数在网页、手机、后端得到相同的展示精度结果；内部先计算后统一舍入。
7. 用户修改 PE 或增长率后，结果更新，系统历史不被覆盖，且不增加第三方数据请求。
8. 保存后新财报到来，旧方案仍可复现；“用最新数据重算”生成新版本。
9. 数据失败或回填中，当前已成功数据仍可见，任务去重、重试和错误状态可验证。
10. 未来目标价计算始终使用同一价格时间作为比较基准，并展示期限和假设。

体验预算为待实测的验收目标：有缓存时当前摘要 p95≤1秒、五年曲线 p95≤2秒；缓存输入的本地参数预览≤150毫秒。首次外部回填走异步状态，不承诺与缓存读取同样快。

### 阶段C：多模型与预测修正

在独立验收后增加 PEG、FCFF DCF、敏感性矩阵、可审核的营收/利润率到 EPS 的经营预测、同一目标日期的预测版本变化，以及手机完整功能。历史 DCF/PEG 先作为有明确版本的重建，不能补造过去不存在的分析师共识。

### 阶段D：扩展

可选加入同行参考、模型适配更多行业、条件提醒、方案分享和更长历史。提醒是新的产品能力，不恢复或默认调用仓库里已退役的预警系统。

排期按阶段A实际覆盖结果和开发资源再估算；不在尚未核验 EPS 历史的情况下承诺具体上线日。

## 11. 评估产品是否有用

优先跟踪：用户能否成功看到目标公司的可用历史，是否查看财报来源或关键假设，以及调整后是否保存和再次查看方案。

建议事件为 `valuation_open`、`history_date_select`、`methodology_open`、`assumption_change`、`scenario_save`、`valuation_unavailable`。不可用原因、覆盖长度和接口失败率用于发现数据问题；不在分析事件中发送用户的私人方案全文。

质量门槛：选定验收样本的快照均能复现，申报有效时间、价格/EPS单位、百分比公式和模型不适用判断全部通过。股票后来上涨不是估值功能正确性的验收标准。

## 12. 外部依据与仍需核验的边界

SEC 官方提供无需 API Key 的 Company Facts 与申报接口，可作为财务事实来源；其标准化覆盖有范围限制，不能把单一接口当成全部财务细节和历史预测档案。[SEC API 官方说明](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)。

yfinance 项目说明默认历史价格会按分红调整，并提醒 Yahoo 数据的用途限制。因此，当前代码可用于技术复用与内部验证，公开上线前需核实既有行情来源的展示权限；“不买新 API”不能自动解决行情授权。若既有权限不覆盖公开展示，应保持内部验证范围或另选满足条件的来源，不能承诺免费公开上线。[yfinance 项目说明](https://github.com/ranaroussi/yfinance)。

DCF 的现金流和折现率必须匹配，具体实施验收需参考企业与股权现金流估值方法。[Damodaran 估值资料](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/valuation/val.htm)。

已确认网页端优先、兼顾手机端。数据覆盖、历史 EPS 可重建性和行情展示权限由阶段A核验，不要求用户先提供技术结论。
