# UI behavior ownership

The maintained `DESIGN.md`, runtime `app/globals.css`, shared UI primitives and
existing sibling workflows own the existing product. This document records the
new virtual-trading workflow; it does not retrofit behavior onto unrelated routes.

## Stock discovery

Source: `../docs/stock-discovery.md` and backend `app/services/stock_discovery.py`.
`StockObservationList` owns all five scopes, local search, ordering, load more,
URL state and detail return. Shared SegmentedControl (desktop), Radix Select
(narrow), ListRow, WatchlistButton, ContentLoading and inline live feedback retain
their canonical behavior. No selection/bulk writes are introduced.

`useMarketDiscovery` uses `useCachedResource` and `useVisiblePolling` for bounded
read caching, stale-request cancellation and minute polling while visible.
Switching ranking scopes shares the same fetched payload. Page refresh refreshes
the active ranking and quotes; rank retries and quote retries remain separate.
Partial-source failures and retained snapshots are labelled; total failure never
falls back to the curated list. Quote reads still use shared per-symbol snapshots.
Entry reasons distinguish dated price moves, full-day average volume multiples,
seven-day opinion counts and curated sector membership in both zh and en.
Node component-state tests cover empty/error/retry/loading, locale, scope state
and detail returns. Real browser geometry/keyboard verification remains pending.

## Virtual trading behavior

- Stock detail `?tab=paper-trading` embeds the canonical OrderTicket with the
  current ticker fixed. `stockPaperTrading` owns per-symbol selection and display
  P&L; `usePaperTradingAccount` owns private reads, serialized mutations and stale
  response handling there. `paperTradingErrors` supplies the same localized
  recovery text as the full trading desk. Account-wide balances are never labelled
  as a single stock's return. The existing shared chart stays visible, research
  tab changes preserve the ticket, and inactive panels pause account polling.

- All execution uses virtual funds. USD, supported-instrument, session and quote
  freshness checks occur on the server; the UI never authorizes a price.
- AI setup links create an editable draft. Quantity is not inferred. Sending an
  order requires checking the draft in the shared Dialog and pressing Place virtual
  order. The same UUID is retained when retrying an uncertain submission.
- Mutations are pessimistic: keep draft/error state until server confirmation.
  Account responses carry versions, and a late response never overwrites a newer
  version. Account mutations serialize in one mounted workspace.
- Background sync never resets an edited ticket or steals focus. Quote lookups
  cancel on symbol changes/unmount. Auto-sync failures retain marks and show a
  persistent stale-data notice; manual sync exposes actionable errors.
- Positions use lot identity; pending closes reserve quantity. Opening orders
  reserve funds. Cancel is a routine action; publishing and withdrawal use explicit
  dialogs describing the visible data and destination.
- Reviews are private until explicitly published. A published review includes
  thesis, executions, fees and net P&L of a completed lot, without account balances.
  Snapshot fields are generated by the backend, never accepted from the browser.
- The learning tab first shows the user's own ledger grouped by position ID,
  including open and partially closed lots. Open P&L is labelled before fees;
  fully closed lots show net realized P&L and can enter the publication dialog.
  Community-feed failures never hide this private journal. With no completed
  lots, the primary action returns to positions or the order ticket with focus.
  Publication drafts remain separate per lot while the learning tab is mounted;
  cancelling the dialog preserves them. Refresh and pagination cancel stale reads.
- Empty, loading, unavailable, rejected and connection-error states are visible.
  Forms retain entered values on failures. Status and error text use live regions.
- The current locale is zh or en through `useCopy` / shared translations. Dates
  display in the device timezone and USD is explicit. Themes inherit semantic
  tokens; all new controls reuse shared primitives and their focus treatment.
- This version uses a transient in-memory ticket, not persistent offline writes.
  Trade/reviews tabs and explicit load-more counts are transient workspace state.

## Verification limits

Database and server behavior are tested in the repository. The learning-review
component was exercised in a local browser with isolated fixture responses:
empty/open/completed trades, community-feed failure, publication failure and retry,
withdrawal, Select Escape behavior, dialog focus restoration and a 390px viewport.
The temporary fixture route was removed. Authenticated end-to-end verification
against a deployed account remains pending; fixture checks do not verify deployment
configuration or live storage. The existing project-wide UI audit findings in
settings, Reddit and global scrollbar ownership remain outside this change.
## Stock valuation

Business source: `../docs/stock-valuation/PRD.md`; implementation scope and
verification: `../docs/stock-valuation/README.md`.

| Capability | Canonical owner | Allowed valuation behavior |
| --- | --- | --- |
| Tabs / segmented controls | Existing Tabs and SegmentedControl | `tab=valuation`; `valuation_view` and `valuation_range` restore reading choices |
| Fields and validation | Shared Input/Label; `lib/stockValuation.ts`; backend Simulation schema | Three PE values and growth rates, 300ms cancellable previews; no browser validation bubbles or persisted writes |
| Loading / feedback | ContentLoading; existing client cache; inline live status | Cold background-build polling, explicit retry, retain readable cached data |
| Sources / disclosure | Native details and validated SEC links | Selected-session financial inputs, split-normalized/original values; progressive assumption editor |
| Table | Native semantic table inside Card | Three future dates; horizontally scrollable on phones, visible scroll hint and keyboard-focusable region |

Simulation requests have no persistent side effects, never call an AI, and never
alter system history. Navigating between visited stock tabs retains transient
parameter state. A new data snapshot resets the editor to its system assumptions;
409 conflicts require refreshing the valuation. Account-saved plans are outside
this first vertical slice. Quotes are labelled completed-session closes; targets
are conditional calculations, not analyst consensus or promised returns.

### Company calculator addition

`ValuationHistoryCard` owns the compact multiple chart: PE for reviewed pilots,
P/S for other companies. It shares the AI flow and the non-pilot history view.
AI valuation only fills ordinary editable scenario fields through
`applyAiAssumptions`; results always come from the existing calculate request.
Saved runs reopen the latest result and can be switched; they are never edited.
`CompanyValuationCalculator` owns the current-company DCF/PE/PEG form;
`lib/companyValuation.ts` owns unit conversion and request validation. The shared
Input/Label, SegmentedControl, Card, Button, ContentLoading and cache remain the
canonical UI owners. `valuation_mode` selects calculator/history; legacy history
parameters open history. Visited views preserve transient state.

This editor uses 350ms cancellable requests and never persists assumptions.
Invalid numbers, crossed scenarios and invalid terminal conditions retain the
last valid same-model result with an explicit stale label. Missing source inputs
remain empty. HTTP 409 exposes Refresh inputs; network failures expose Retry.
Financial refresh retains edited fields and scenario assumptions, updating only
untouched defaults. Changing companies resets the editor. The older history PE
editor still resets to system assumptions on a new historical snapshot.

DCF results distinguish enterprise value, equity value and per-share value. PE
and PEG display equity value only. Required financial basis and dated quote are
visible with results. Native disclosures contain editable financial inputs,
their vendor/assumption origins, source links, forecast and sensitivity tables.

## Market quote freshness

- `hooks/useMarketQuotes.ts` owns list quote polling; `useStockData.ts` owns
  single-stock readers. Both reuse `useVisiblePolling`: 15 seconds while visible,
  with revalidation on focus, visibility return and reconnection. `quoteSnapshots`
  publishes a shared per-symbol price to `clientCache` subscribers, reconciles
  each session by its source timestamp and guards against late-response rollback
  even when the general cache evicts a large list. Each browser page owns its
  independent memory cache; no cross-window simultaneous delivery is promised.
- `ChartView` refreshes current candles every minute and on return without resetting
  the inspected point, zoom or drawings. Immutable saved snapshots disable polling.
- `lib/chart/quote.ts` selects extended hours only with a matching timestamp newer
  than the regular quote. `PriceGraph` distinguishes source quotes, historical
  candles, session baselines, unknown timestamps and refresh failures. Single-quote
  failures are HTTP 503; no zero-price success is fabricated. Browser/CDN quote
  and history responses use no-store; bounded in-memory caches own freshness.
- Main quote values use the regular session across lists and charts. Extended
  prices and their source timestamps are separate. Financial ratios, historical
  closing-price comparisons and dated valuation inputs retain snapshot labels.
- The private OrderTicket polls its server-validated quote every 15 seconds while
  active, pauses during review/submission or inactive tabs, preserves form inputs
  and retains the last genuine quote with an error on refresh failure. Its quote
  never authorizes execution in the browser; server validation remains decisive.
- Regression evidence: `chart-live-quote`, `chart-view-integration`,
  `stock-quote-polling`, `market-quotes` and `market-history-proxy` Node tests;
  backend `test_yfinance_quotes.py`; TypeScript check and local HTTP quote/history
  flow. Browser layout/interaction QA remains unverified because local browser
  control is disabled in Work settings.
- Additional regression evidence: `market-quote-sync`, `quote-snapshots`,
  `landing-quotes`, `stock-discovery`, `stock-news`, Watchlist and virtual-trading
  tests. Five live local symbols (NVDA/AAPL/MSFT/TSLA/AMD) returned identical full
  batch and single-quote responses with no-store headers and server cache hits.
